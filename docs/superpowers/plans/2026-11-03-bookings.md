# Bookings Implementation Plan

> **For agentic workers:** REQUIRED SUB-SKILL: Use superpowers:subagent-driven-development (recommended) or superpowers:executing-plans to implement this plan task-by-task. Steps use checkbox (`- [ ]`) syntax for tracking.

**Goal:** Every ticket and bed Simon has paid for is in the app, green, with its reference and attachments one tap away, entered by hand, from the picked flight, or by Claude through the connector.

**Architecture:** A new owner only `bookings` table and a private `bookings` Storage bucket in Supabase, read live by the planner through supabase-js and realtime like trips, and written by the connector through a new `booking` type in `latam_trip_mcp/core.py`. A booking is matched to legs and stops by its ends and day, never by trip, through pure helpers in `planner/src/lib/booked.ts`. The views are a Wallet style booking view, a Mark as booked sheet and a green booked state on the route, the trips list and the flight sheet.

**Tech Stack:** Postgres and Supabase Storage (SQL migrations), Python 3 (unittest), React 19, TypeScript, Zustand, supabase-js, Vitest.

**Spec:** `docs/superpowers/specs/2026-11-03-bookings-stays-ways-design.md`, section 4. The anti goals and constraints at the top of the spec bind every task.

## Review Focus

1. A long haul return ticket marked booked from the picked flight. Two rows with one `ticket` group, the price on the first row and 0 on the second, and the trip total counts the ticket once.
2. A booking whose ends match a leg but whose day is not the leg's day. The leg is not green and shows "Booked on {day}" instead, and a booking with the same ends on the leg's day turns it green in every trip that has that leg.
3. A cancelled booking never counts as booked anywhere, in totals, rings, the trips list count or warnings.
4. Attachments: a file over 10 MB or of another type is refused with a plain message before upload, and a signed URL is fetched only when a tile is opened, never stored.
5. Signed out or offline: the bookings list is empty without errors and the rest of the planner works as today.
